Про self-host йдеться окремо, у [Резервні копії та відновлення](/dev/self-host/backup-restore/).
Ця сторінка про хмарний прод: базу `projectk-prod-new` і сховище `stprojectkprodnew`.

## Що зберігається

| Що | Глибина | Хто робить |
|---|---|---|
| База, відновлення на будь-яку точку часу | 7 днів | Azure SQL, автоматично |
| База, тижнева копія | 8 тижнів | LTR |
| База, місячна копія | 12 місяців | LTR |
| Файл, видалений | 30 днів | мʼяке видалення блоба |
| Файл, перезаписаний | 30 днів | версіонування |
| Контейнер, видалений | 30 днів | мʼяке видалення контейнера |

Річних копій немає навмисно: у базі персональні дані неповнолітніх, і тримати їх у бекапах роками
без потреби не варто.

Старі версії блобів прибирає правило життєвого циклу `expire-old-blob-versions` через 30 днів.
Поточна версія файлу не видаляється ніколи, поки її не видалить сам застосунок.

## Відновити базу

На точку часу в межах семи днів:

```bash
az sql db restore --subscription projectk-prod-sub -g rg-projectk-prod-paid -s sql-projectk-server-prod-new -n projectk-prod-new --dest-name projectk-restore-check --time 2026-09-15T12:00:00Z
```

З тижневої чи місячної копії спершу знайди її, потім відновлюй за `--backup-id`:

```bash
az sql db ltr-backup list --subscription projectk-prod-sub -l polandcentral -s sql-projectk-server-prod-new -d projectk-prod-new -o table
```

Відновлення завжди створює **нову** базу, поточну воно не чіпає. Це і є безпечний шлях: підняти
копію поруч, звірити дані, і лише потім перемикати рядок підключення в App Service.

## Відновити файл

Видалений файл повертається зі стану «мʼяко видалений», перезаписаний — з попередньої версії.
І те, і те видно в порталі на вкладці сховища, якщо увімкнути показ видалених блобів і версій.

## Чого ця схема не закриває

Усі копії живуть у тій самій підписці, що й дані, і під тим самим акаунтом. Втрата доступу до
акаунта Azure забирає і прод, і бекапи разом. Копію поза Azure описує задача `SEC-3.3`; вона
потребує бакета R2, токена тільки на запис і публічного ключа `age`.

## За чим стежити

LTR не коштує нічого, доки сумарний обсяг бекапів не перевищує стелю бази, тобто 2 ГБ. При базі
в 28 МБ запас приблизно чотирнадцятикратний. Коли база підросте до кількох сотень мегабайтів,
кількість копій варто переглянути.
