# Лілейка — брендбук і дизайн-система

Візуальна система для **ProjectK** — системи управління пластунським куренем.
Версія 1.1 · остання правка: 2026-07-27

---

## 0. Швидкий контекст (читати першим, особливо якщо ти AI-агент)

**Продукт.** Самохостована система для одного куреня НСОУ «Пласт»: реєстр учасників, планування сходин, точкування, вмілості, документи. Один розробник, малий проєкт, свідомо мінімальний обсяг UI.

**Стек.** Angular 21 (standalone components, signals + RxJS) · PrimeNG 21 з темою Aura · Tailwind 4 (`@import "tailwindcss"` + `tailwindcss-primeui`) · .NET backend. Фронтенд: `Frontend/projectk-frontend`.

**Дві назви — не помилка:**
| Назва | Де вживається |
|---|---|
| **Лілейка** | продукт: вітальна сторінка, шапка сайдбара, `<title>`, листи, розмова з користувачем |
| **ProjectK** | код: репозиторій, README, Docker, env-змінні, CI, назви пакетів |

Ніколи не перейменовуй технічні артефакти на «Лілейка» і ніколи не показуй «ProjectK» користувачу в UI (крім рядка версії).

**Десять правил, які покривають 90% рішень:**

1. Один зелений (`#0E6E4E`), один теплий (`#D9762F`), чорнило, поверхня. Більше кольорів не вводити.
2. Терракота — тільки статуси й акценти. Ніколи не кнопка, не посилання, не «успішно».
3. Один шрифт в інтерфейсі: **Manrope**. Рукописний **Neucha** — тільки логотип і порожні стани.
4. Рамка 1px, ніколи 2px. Кольорових лівих смужок у картках немає.
5. Радіуси: `8px` інтерактивне, `12px` картки й панелі.
6. Тіні — тільки модалки, дропдауни й скриншоти в маркетингу. Картки живуть на рамці.
7. Ховер = зміна фону на `surface` або рамки на `primary`. Без зсувів, масштабу й анімації розміру.
8. Порожні стани обовʼязкові й мають голос. Один рукописний рядок, один рядок пояснення, одна дія.
9. Іконки — `pi pi-*` з PrimeIcons, які вже є в проєкті. Нових наборів не додавати, SVG не малювати.
10. Емодзі в UI немає. Ніде.

**Що НЕ можна змінювати:** червона табличка з числом куреня (`kurin-number.css`, `#b30003` / `#ff0005`) — це пластова відзнака, а не елемент бренду. Див. §7.

## 1. Знак

Лілейка з трьох листків зі стеблом і поперечкою. Оригінальний знак — офіційна емблема НСОУ «Пласт» (лілея з тризубом) **не використовується і не відтворюється**.

### Файли

| Файл | Призначення |
|---|---|
| `assets/lilyka-mark.svg` | основний, двоколірний (зелений + терракотовий центральний листок) |
| `assets/lilyka-mark-mono.svg` | `currentColor`, без центрального листка — для вбудовування в HTML |
| `assets/lilyka-mark-dark.svg` | для темного фону (`#34C48D` + `#EE9A5A`) |
| `assets/favicon.svg` | 64px, знак на зеленому квадраті `r=14` |
| `assets/favicon-16.svg` | спрощений — два листки, без стебла й поперечки |

### Правила

- **Мінімальний розмір із поперечкою — 24px.** Менше — версія `favicon-16` (два листки).
- **Вільне поле** навколо знака — висота одного листка (≈ 25% висоти знака).
- Товщина обведення масштабується: 6 при 96px+, 7–8 при 32–48px, 12–16 при 16px. Знак завжди `fill="none"`, `stroke-linecap="round"`.
- Центральний листок терракотовий **тільки** на світлому фоні й на зеленому банері. В одноколірній версії — той самий колір, що решта.
- Не обертати, не заливати, не додавати тінь, обведення чи градієнт. Не ставити в коло, крім аватарки користувача.

### Логотип (lockup)

Знак + слово «Лілейка» у Neucha, горизонтально, відступ між ними = 0.4× висоти знака, вирівнювання по оптичному центру. Вертикального варіанта немає — не вигадувати.

### Терракота — вичерпний список місць

Дозволено: тег «Незабаром» · крапка «є що модерувати» в сайдбарі · банер cold start · іконка `pi-sparkles` у «Зроблено пластунами для пластунів» · центральний листок знака · акцентне слово в маркетинговому заголовку («свисти **алярми**»).

Заборонено: кнопки, посилання, статус «успішно», графіки, фони секцій, hover-стани, рамки карток.

**Правило одної плями:** на будь-якому екрані терракота зʼявляється не більше ніж в одному місці одночасно. Якщо їх два — одне з них не потрібне.

| severity | Значення | Колір |
|---|---|---|

| `danger` | ліміт, помилка, видалення | червоний з Aura |
| `secondary` | роль, службова мітка | `faint` |

| Роль | Шрифт | Розмір | Вага | Tracking |

| h3 / заголовок картки | Manrope | 17px | 800 | −1% |
| body | Manrope | 15px | 400 | 0 |
| UI (кнопки, меню) | Manrope | 15px | 600–700 | 0 |
| підпис / мета | Manrope | 13px | 400–600 | 0 |
| мікропідпис | Manrope | 11px | 700, uppercase | +18% |
| логотип | Neucha | 29–50px | 400 | 0 |
| порожній стан — заголовок | Neucha | 24px | 400 | 0 |
| код, версія, ключі | ui-monospace | 11–12px | 400 | 0 |

Line-height: 1.02 для великих заголовків, 1.15 для h2–h3, 1.5–1.55 для тексту, 1.45 для дрібного.

### Чому не Karla і не Patrick Hand

Перша редакція брендбука називала Karla й Patrick Hand. **Жоден із них не має кириличного набору** — весь український текст падав на `system-ui` і виглядав по-різному на кожній ОС. Замінено на **Manrope** (той самий нейтральний гротеск, ваги 400–800) і **Neucha** (рукописний), обидва з повною кирилицею.

Neucha при однаковому кеглі дає ascent приблизно на 10% нижчий за Patrick Hand, тож розміри рукописного в таблиці підняті рівно настільки — оптично це той самий рядок.

### Підключення

Шрифти **локальні**, не з CDN: самохост має підніматись без інтернету.

```
public/assets/fonts/
├── manrope-var-cyrillic.woff2      ← варіативний, 400–800
├── manrope-var-latin.woff2
├── manrope-var-latin-ext.woff2
├── neucha-400-cyrillic.woff2
└── neucha-400-latin.woff2
```

`@font-face` — у секції 0 `lilyka-theme.css`, з `unicode-range` від Google Fonts. Кирилиця Manrope додатково в `<link rel="preload">` у `index.html`: нею набрано весь інтерфейс. Разом ~112 kB.

**Neucha не використовується ніде, крім логотипу й заголовків порожніх станів.** Не в кнопках, не в тегах, не в тултипах, не в заголовках сторінок.

## 4. Ритм, форма, рух

**Відступи.** Крок 4px. У реальному вжитку: `8 · 12 · 14 · 20 · 28 · 56`. Внутрішній відступ картки — 20px (мобільний 16px), панелі — 24px, секції сторінки — 56px.

**Ширина контенту.** `min(100% - 2rem, 72rem)` — так уже зроблено в `kurin-panel.component.css`, лишається.

**Радіуси.** `8px` — кнопки, поля, теги, пункти меню. `12px` — картки (`.kurin-tile`), панелі, модалки. `14px` — favicon, hero-ілюстрація. `50%` — тільки аватарки й крапки-індикатори.

**Рамки.** Завжди `1px solid var(--lil-line)`. Ніяких 2px, ніяких кольорових лівих смужок, ніяких подвійних рамок. Пунктирна рамка (`1px dashed`) — тільки порожні стани й вимкнені елементи.

**Тіні.** Дозволено: модалка/дропдаун (`0 12px 40px rgba(16,20,19,0.07)`), скриншот продукту в маркетингу (`0 20px 52px rgba(16,20,19,0.10)`). Все інше — без тіні. Наявна тінь `.kurin-tile` (`0 8px 26px -22px …primary…`) прибирається.

**Ховер.** Фон → `surface` (світла) / `hover-bg` (темна), або рамка → `primary`. Перехід `background-color 120ms ease, border-color 120ms ease`. Без `transform`, без `box-shadow`, без зміни розміру.

**Вимкнено.** `opacity: 0.4` + пунктирна іконка. Не сірий текст — прозорість, щоб було видно, що елемент є, але поки не працює.

**Анімація.** Максимум 200ms, `ease`. Плавний рух є лише в трьох місцях: пунктирна лінія в порожньому стані (`stroke-dashoffset`, 1.6s linear infinite), спінер cold start, поява дровера. Логотип на вітальній може мати легке коливання 6s — більше ніде.

## 5. Компоненти

Усі — PrimeNG. Нові компонентні бібліотеки не додавати.

### Кнопки

| Варіант | Коли | PrimeNG |
|---|---|---|
| primary заповнена | головна дія екрана, одна на екран | `<p-button label="Зберегти" />` |
| secondary контурна | альтернативна дія | `severity="secondary"` |
| text | третинна, «Скасувати», «Розгорнути» | `severity="secondary" variant="text"` |
| з іконкою | завжди `iconPos="left"`, крім «Відкрити →» | `icon="pi pi-plus"` |
| icon-only | тулбар, дії в рядку таблиці | `text severity="secondary"` |

Висота 40px (`size="small"` 34px), горизонтальний відступ 20–28px. `severity="info"` для кнопок **не використовувати** — у поточному коді (`kurin-panel`) вона стоїть на «Створити» / «Додати учасника»; замінити на дефолтну primary.

### Поля введення

Мітка над полем: 13px, `faint`, вага 600. Поле: рамка `line`, радіус 8px, висота 40px, фокус — рамка `primary` + `outline: 2px solid primary-50`. Помилка — рамка `danger` + рядок 13px під полем. Форма — `display: grid; gap: 1rem`, три колонки на десктопі, одна на мобільному (як уже в `.profile-form`).

### Картка / плитка

`.kurin-tile` — базовий контейнер контенту:

```css
.kurin-tile {
  background: var(--p-content-background);
  border: 1px solid var(--p-content-border-color);
  border-radius: 12px;
  box-shadow: none;
  padding: 1.25rem;
}
```

Заголовок картки — 17px/800, під ним підпис 13px `muted`. Дія картки — праворуч у тому ж рядку, `margin-left: auto`.

### Таблиці (`.project-table`)

Хедер: 11px, uppercase, tracking +18%, `faint`, фон `surface`, без рамок між колонками. Рядок: висота 52px, розділювач `1px line`, ховер — фон `surface`. Головна колонка — назва 15px/650 + мета 13px `muted` під нею (як `.group-name-cell`). Колонка дій — праворуч, фіксована ширина, кнопки icon-only або splitButton. Мобільний — рядок стає flex, хедер `display: none` (уже реалізовано, лишається).

Порожня таблиця — **не** `p-message`, а порожній стан із §6.

### Теги (`p-tag`)

Радіус 6px, 11px/700, відступ `3px 9px`. Роль користувача — `secondary`. «Незабаром» — `info` (зелений, не синій). «Очікує модерації» — `warn` (терракота). Ліміт CBT — `danger` при досягненні, інакше `info`.

### Тулбар

Висота 56px, фон `paper`, нижня рамка `1px line`, без тіні. Ліворуч — бургер (`pi pi-bars`, text secondary). Праворуч — дзвіночок нотифікацій і вихід, `gap: 0.35rem` (уже в `.toolbar-actions`). Логотипа в тулбарі немає — він у сайдбарі.

### Сайдбар (`p-drawer` headless)

Шапка — зелений банер: фон `primary`, `padding: 1.25rem`, знак 32px білим + «Лілейка» Neucha 31px білим. Замінює `<h2>Project K</h2>`.

Пункти: висота 42px, `gap: 0.75rem`, радіус 8px, 15px/600 `ink-soft`. Активний — фон `primary-50`, текст і іконка `primary`, вага 700. Вимкнений — `opacity: 0.4` + пунктирна іконка. Індикатор «є що модерувати» — крапка 7px терракотою праворуч, без числа.

Низ: рядок версії 11px monospace `faint`, під ним рамка й блок користувача — іконка, e-mail 13px, тег ролі.

**Порядок пунктів не змінювати** — він залежить від ролей і будується в `sidebar-menu.ts`.

### Модалки й дровери

Фон `paper`, радіус 12px, тінь `0 12px 40px rgba(16,20,19,0.07)`, заголовок 20px/800, підкладка `rgba(16,20,19,0.32)`. Дії — праворуч знизу, `gap: 0.5rem`, порядок: text «Скасувати», потім primary.

### Порожній стан

Обовʼязковий скрізь, де може не бути даних. Структура:

```html
<div class="lil-empty">
  <!-- проста лінія/фігура, stroke: line, 110×66 -->
  <div class="lil-empty__title">Тут ще нікого немає</div>
  <div class="lil-empty__body">Додай першого юнака — і реєстр почне жити.</div>
  <p-button label="Додати учасника" />
</div>
```

Рамка `1px dashed`, радіус 12px, `padding: 1.5rem`, вирівнювання по центру, `gap: 0.875rem`. Ілюстрація — обведені прості фігури (кола, прямокутники, лінії) кольором `line`, одна деталь терракотою. Ніяких намальованих сцен і персонажів.

### Cold start banner

Наявний компонент лишається за структурою. Кольори: фон `accent-50`, рамка `1px accent-100`, текст `accent-700`, спінер `accent`. Заголовок 15px/700, повідомлення 13px.

## 6. Каталог whimsy-меседжів

Формула: **рукописний заголовок (без крапки) + рядок пояснення (з крапкою) + одна дія**. Заголовок описує стан, а не наказує. Гумор — тихий, пластовий, без жартів про користувача.

| Місце | Заголовок | Пояснення | Дія |
|---|---|---|---|
| Реєстр порожній | Тут ще нікого немає | Додай першого юнака — і реєстр почне жити. | Додати учасника |
| Планування порожнє | Календар ще спить | Перша сходина в плані — і він прокинеться. | Створити планування |
| Точкування порожнє | Точкування чисте | Ще ніхто не заробив і не втратив пункта. | Поставити точки |
| Пошук без результатів | Нічого не знайшлось | Спробуй коротший запит — або перевір гурток. | Скинути фільтри |
| Гуртки порожні | Гуртків поки немає | Курінь без гуртків — як мандрівка без стежки. | Створити гурток |
| Вмілості порожні | Вмілостей ще немає | Заявки на вмілості зʼявляться тут. | — |
| Модерація порожня | Все розглянуто | Заявок на вмілості немає. Можна відпочити. | — |
| Документи (незабаром) | Документи в дорозі | Статути й накази житимуть тут. Скоро. | — |
| Cold start | Сервер ще прокидається | Самохост після сну. Дай йому пів хвилини. | Пробуємо знову… |
| 403 | Сюди тобі не можна | Ця сторінка для впорядників. Твоя роль — юнак. | На мій профіль |
| 404 | Такої стежки немає | Можливо, посилання застаріло. | На головну |
| 500 | Щось пішло не так | Ми вже знаємо. Спробуй за хвилину. | Оновити |
| Офлайн | Звʼязку немає | Перевір інтернет — дані збережені локально. | — |
| Успішне збереження (toast) | Збережено | — | — |

Toast-повідомлення **не** рукописні й не жартівливі: «Збережено», «Учасника додано», «Не вдалося зберегти». Whimsy живе тільки в порожніх станах і на екранах помилок.

## 7. Захищені елементи

**Число куреня** (`kurin-number.css`) — біле число на червоному полі `#b30003` з рамкою `#ff0005`, Arial. Це відтворення пластової курінної таблички, а не елемент бренду. **Не перефарбовувати в зелений, не змінювати шрифт, не додавати радіус.** Єдине, що дозволено — розміри для адаптиву (уже є).

**Ілюстрація `scouts-main.png`** — лінійна графіка пластунів, чорна. Лишається чорною на світлому фоні. Не тонувати в зелений, не інвертувати. У темній темі — на світлій підкладці `#F7F9F8` з радіусом 16px.

## 8. Тон копірайтингу

- Звертання на «ти», не на «Ви». Це система для своїх.
- Пластова термінологія без пояснень: курінь, гурток, юнак, впорядник, сходина, точкування, вмілість, алярм, станиця, край.
- Короткі речення. Одна думка — одне речення.
- Заголовки кнопок — дієслово в інфінітиві: «Додати учасника», «Створити планування», «Зберегти».
- Не писати «будь ласка», «на жаль», «упс», «ой». Не вигукувати.
- Не пояснювати очевидне. «Додати учасника» не потребує підпису «натисніть, щоб додати учасника».
- Технічні терміни в UI українською: не «submit», а «Надіслати». Виняток — назви ролей (`Admin`) і технічні ключі.

**Назва системи** береться з `environment.appName` (runtime-конфіг `PROJECTK_APP_NAME`). Дефолт — «Лілейка» в усіх середовищах: `src/environments/*.ts`, `docker/compose.app.yml`, `docker/nginx/40-projectk-env.sh`, `docker/selfhost/compose*.yml`. Самохостер може перезаписати змінною; у коді дефолт більше не «ProjectK».

### Що йде в preset, а що в CSS

Не все перекривається через CSS-змінні. PrimeNG вставляє свою тему в `<head>` **після** `styles.css`, тож:

- **Тільки в `lilyka-preset.ts`:** компонентні токени (`tag`, `message` — Aura бере `info` з `{sky.*}`, а `warn` з `{orange.*}`), шкала `primitive.borderRadius`, `semantic.colorScheme.*.text`. Змінні `--p-info-*` / `--p-warn-*` із теми до них не доходять.
- **Темна схема Aura читає `surface` навпаки:** `surface.0` — це колір тексту, `900` — фон контенту, `950` — тло, `700` — рамка. Шкала йде від світлого до темного, інакше буде темний текст на темному тлі.
- **У CSS однокласові селектори (`.p-tag`, `.p-toolbar`) потребують префікса `:root`** — інакше програють темі PrimeNG за порядком у каскаді.

`app.config.ts`:

```ts
import { LilykaPreset } from './lilyka-preset';

providePrimeNG({
  translation: { /* без змін */ },
  theme: {
    preset: LilykaPreset,
    options: { darkModeSelector: '[data-theme="dark"]' }
  }
})
```

Окремі класи, які додає `lilyka-theme.css`: `.lil-wordmark` (логотип) · `.lil-sidebar-brand` (шапка сайдбара) · `.lil-empty`, `.lil-empty__art`, `.lil-empty__title`, `.lil-empty__body`, `.lil-empty__accent`, `.lil-empty__dash` (порожній стан). Плюс перевизначення `.kurin-tile`, `.project-table`, а також `:root .p-toolbar`, `:root .p-tag`, `:root .p-panelmenu.lil-menu`.

### Порожній стан у коді

Розмітку `.lil-empty` руками не писати — є `app-empty-state` (`src/app/shared/empty-state/`):

```html
<app-empty-state art="list" title="Тут ще нікого немає"
                 body="Додай першого юнака — і реєстр почне жити.">
  <p-button label="Додати учасника" icon="pi pi-plus" (onClick)="create()" />
</app-empty-state>
```

`art` — `trail` (типово), `list`, `calendar`. Дія проєктується через `ng-content`: якщо прав немає, просто не передавай нічого. Текст брати з каталогу §6.

**Якщо та сама дія вже є в шапці списку — сховати її, поки список порожній.** Інакше на екрані дві однакові primary-кнопки, що суперечить §5.

Кольори пунктів меню живуть у `navigation.item.*` у preset, а не в CSS: PrimeNG фарбує обгортку `.p-panelmenu-*-content`, тож правило на вкладене посилання дає два накладені прямокутники на ховері.

## 11. Довідник для агента: типові задачі

**«Додай новий екран.»** Обгортка `<section class="kurin-tile">` у контейнері `width: min(100% - 2rem, 72rem); margin-inline: auto`. Заголовок h1 28px/800. Дані — `p-table styleClass="project-table"` або `dl.identity-grid`. Обовʼязково порожній стан із каталогу §6.

**«Додай кнопку.»** Одна primary на екран. Решта — `severity="secondary"` або `variant="text"`. `severity="info"` не використовувати.

**«Зроби це помітнішим.»** Спочатку вага шрифту й розмір, потім `primary`, і лише в крайньому разі терракота — і тільки якщо її на екрані більше немає.

**«Додай іконку.»** Знайти в PrimeIcons (`pi pi-*`). Якщо нема — обійтися без іконки. Не малювати SVG, не додавати бібліотеку.

**«Додай нову сутність у меню.»** Тільки через `buildItems()` у `sidebar-menu.ts`, з перевіркою прав через `PermissionService`. Порядок наявних пунктів не змінювати.

**Чого не робити без запиту:** не додавати градієнти, не вводити третій колір, не міняти шрифт, не додавати анімації понад §4, не перефарбовувати число куреня, не додавати емодзі, не переписувати `scouts-main.png`.
